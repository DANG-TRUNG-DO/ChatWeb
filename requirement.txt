# Realtime Chat Web - Requirement

1. MỤC TIÊU

Xây dựng một ứng dụng Web Chat Realtime với các chức năng cơ bản tương tự Messenger/Telegram. Dự án tập trung vào Backend, Realtime Communication và kiến trúc có khả năng mở rộng trong tương lai.

Kiến trúc ban đầu sử dụng Modular Monolith, tránh over-engineering bằng Microservices ở giai đoạn đầu.

4. FUNCTIONAL REQUIREMENTS

Authentication:
- Register / Login / Logout.
- JWT Access Token + Refresh Token.
- Password hashing.
- Authentication cho REST API và WebSocket.

User:
- Xem và chỉnh sửa profile.
- Search user.
- Avatar.
- Online / Offline status.

Conversation:
- Direct Chat.
- Group Chat.
- Tạo/xóa conversation.
- Thêm/xóa member.
- Conversation list.
- Group roles: OWNER, ADMIN, MEMBER.

Messaging:
- Gửi và nhận tin nhắn realtime.
- Message types: TEXT, IMAGE, FILE.
- Edit / Delete / Reply message.
- Message history.
- Read / Unread.
- Cursor-based pagination.

Realtime:
- WebSocket endpoint: /ws.
- Client gửi message qua /app/...
- Client subscribe conversation qua /topic/conversation/{id}.
- Events: MESSAGE_SENT, MESSAGE_UPDATED, MESSAGE_DELETED,
  MESSAGE_READ, TYPING, USER_ONLINE/OFFLINE.

Message phải được lưu vào PostgreSQL trước khi broadcast.

5. DATABASE & REDIS

PostgreSQL tables chính:

users
refresh_tokens
conversations
conversation_members
messages

PostgreSQL là source of truth.

Yêu cầu:
- Flyway migration.
- Index cho message history.
- Cursor pagination.
- Read/unread lưu theo last_read_message_id.

Redis sử dụng cho:
- User presence.
- Cache.
- WebSocket distributed state.
- Rate limiting.

Redis không lưu message như nguồn dữ liệu chính.
